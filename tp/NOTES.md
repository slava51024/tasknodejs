# NOTES

## Вариант

Порядковый номер: **1**.

По таблице задания номера 1–4 соответствуют варианту **V = 0 — склад запчастей**. Обязательное поле — `serialNumber` в формате `XX-0000`. Персональное правило: при создании нужно проверять формат регулярным выражением, а одинаковые `serialNumber` запрещены.

## 1. Почему на DELETE возвращается 204, а не 200?

`204 No Content` означает, что операция выполнена успешно, но сервер не возвращает тело ответа. Для удаления это удобно: после успешного `DELETE` удаленный объект уже не нужно отправлять клиенту.

## 2. Что произойдет с данными при перезапуске сервера?

Данные хранятся в массиве `items` в оперативной памяти процесса Node.js. При остановке процесса массив исчезает. После нового запуска `seed()` снова создает одну стартовую запись, потому что N = 1. База данных или файл здесь не используются.

## 3. Зачем нужен next(err)?

`next(err)` передает ошибку следующему обработчику Express, в нашем случае централизованному `errorHandler`. Если убрать передачу ошибки и не обработать исключение другим способом, запрос может зависнуть или ошибка будет обработана некорректно, а централизованный обработчик не получит ее.

## 4. Как реализовано персональное правило варианта?

Проверка формата находится в `src/middlewares/validateItem.js`:

```js
const SERIAL_NUMBER_RE = /^[A-Z]{2}-\d{4}$/;

if (typeof serialNumber !== "string" || !SERIAL_NUMBER_RE.test(serialNumber)) {
  return res.status(400).json({
    error: "serialNumber должен быть в формате XX-0000, например AB-1234"
  });
}
```

Проверка выполняется для `POST` и `PUT` через middleware.

Запрет одинаковых `serialNumber` также реализован в `src/middlewares/validateItem.js` через поиск существующей записи с таким же номером (при `PUT` текущая запись исключается):

```js
const items = require("../services/store");
const duplicate = items.some((item) => item.serialNumber === serialNumber);

if (duplicate) {
  return res.status(400).json({
    error: "Запчасть с таким serialNumber уже существует"
  });
}
```

## 5. Где приложение может упасть и как это обработано?

Ошибки во время выполнения контроллеров передаются через `next(err)` в `errorHandler`. Централизованный обработчик возвращает `500` и не раскрывает внутреннюю информацию об ошибке клиенту.

Неизвестные URL обрабатывает `notFound.js` и возвращает `404`.

## Структура

- `routes` — маршрутизация.
- `controllers` — получение данных из запроса и формирование ответа.
- `services` — вся работа с массивом.
- `middlewares` — валидация и обработка ошибок.
- `seed.js` — создание N стартовых записей.
- `app.js` — настройка Express.
- `server.js` — запуск приложения и загрузка `.env`.
